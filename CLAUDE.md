# Convert

Local file converter: right-click files in the file manager → **Convert…** → pick a format → the new
file lands next to the original (`song.opus` → `song.mp3`, then `song 2.mp3` if that exists). Nothing is
uploaded; every conversion runs on the machine. Open source (MIT), upstream at
github.com/newtonstudios/convert.

The repo holds two independent apps that share the same behaviour and format list but no code:

| | macOS (original) | Windows (port, in progress) |
|---|---|---|
| Location | `Sources/Convert/` (Swift, SwiftUI) | `windows/` (C#, .NET 10, WPF Fluent theme) |
| Entry from file manager | Finder Quick Action (Automator workflow in `~/Library/Services`) | Windows 11 context menu via `IExplorerCommand`, registered by a sparse MSIX package |
| Audio / video | `ffmpeg` (Homebrew) + VideoToolbox | `ffmpeg.exe` (bundled `tools\` folder or PATH / winget) + NVENC / QSV / AMF |
| Images | ImageIO, `cwebp` for WebP | Magick.NET (HEIC, AVIF, WebP, RAW included) |
| Documents | `textutil`, built-in Markdown renderer, AppKit → PDF | Markdig, WebView2 `PrintToPdfAsync` for → PDF, LibreOffice (optional) for Office formats |
| PDF → images / text | Core Graphics, PDFKit | `Windows.Data.Pdf` (built into Windows), PdfPig |
| Build | `./build.sh` | `windows/build.ps1` |

**When changing behaviour, keep both apps in step**: the format list, target IDs, defaults and option
ranges (`Formats.swift` ↔ `windows/src/Convert.Core/Formats.cs`) are meant to match. Where a platform
can't do something (e.g. HE-AAC needs `libfdk_aac`, which standard Windows ffmpeg builds lack), the target
is hidden at runtime rather than failing.

## Product rules (both platforms)

- Never overwrite: outputs use the next free name (`name.ext`, `name 2.ext`, …). A multi-page PDF →
  images goes into a folder `name pages/` with `page 1.png`, `page 2.png`, …
- Batches: many files of one kind convert one after another with a single progress bar. Audio and video
  can be mixed (a video can become audio). Only output groups valid for *every* selected file are offered.
- "Move original to Trash / Recycle Bin" only after the new file exists on disk; never deletes for good.
- Settings live behind a collapsed **Advanced** section and are remembered per target format; the last
  chosen target is remembered per kind of selection.
- No network code, no analytics, no accounts.
- UI text is English.

## macOS app

```bash
./build.sh             # builds build/Convert.app (universal, ad-hoc signed)
./build.sh --install   # also copies to ~/Applications and installs the Quick Action
swift test             # unit tests (Tests/ConvertTests)
build/Convert.app/Contents/MacOS/Convert --cli mp3 song.opus   # convert from the command line
```

Key files: `Formats.swift` (detection, targets, options), `FFmpeg.swift` (ffmpeg args),
`ImageConv.swift`, `DocConv.swift` (documents + PDF), `Markdown.swift`, `ConvertModel.swift` +
`ContentView.swift` (window), `QuickAction.swift` (Finder integration). Requires macOS 14+, Xcode 15+.

## Windows app (`windows/`)

```
windows/
  Convert.slnx
  build.ps1                  # build + package (+ -Install to register the context menu)
  uninstall.ps1              # -All also removes settings and the cert
  tools/                     # not committed: SDK build tools (makeappx, signtool), optional ffmpeg\ to bundle
  src/Convert.Core/          # all conversion logic, no UI (formats, ffmpeg, images, docs, PDF)
  src/Convert/               # WPF app (the window); also --cli for scripted conversions
  src/Convert.Shell/         # IExplorerCommand COM server (comhost) = the context-menu entry
  packaging/                 # AppxManifest.template.xml, Assets/ (icon, logos)
  tests/Convert.Core.Tests/  # xUnit, run real conversions against generated media
```

```powershell
cd windows
dotnet build                          # build everything
dotnet test                           # tests (need ffmpeg on PATH or in tools\)
.\build.ps1 -Install                  # publish to %LOCALAPPDATA%\Programs\Convert, sign + register the
                                      # sparse package (one UAC prompt the first time to trust the cert)
.\uninstall.ps1                       # remove package and installed files
src\Convert\bin\Debug\net10.0-windows10.0.19041.0\win-x64\Convert.exe --cli mp3 song.opus
```

### How the context menu works

- Windows 11's top-level context menu only shows `IExplorerCommand` handlers from apps with **package
  identity**. Convert gets that through a *sparse package*: a tiny signed MSIX that contains only the
  manifest and logos and points at the normal install folder via `-ExternalLocation`.
- The manifest (`packaging/AppxManifest.xml`, generated by `build.ps1`) registers
  `Convert.Shell.comhost.dll` as a `com:SurrogateServer` (runs in `dllhost.exe`, not in Explorer) and one
  `desktop5:ItemType` per supported extension, so the handler is only loaded for files Convert can handle.
  The extension list comes from `Convert.exe --list-extensions` — `MediaKinds.cs` is the single source.
- `Convert.Shell` must stay tiny: it shares only `MediaKinds.cs` (linked source) with Core and never loads
  Magick.NET or WPF. `Invoke` starts `Convert.exe` with the selected paths (or `--files <listfile>` when
  the command line would get too long).
- The package is signed with a self-signed cert `CN=Convert Dev` (created on first `build.ps1 -Install`,
  stored in `CurrentUser\My`, public part in `LocalMachine\TrustedPeople`). Publisher in
  `AppxManifest.xml`, `app.manifest` (`<msix>` element) and the cert must match.
- `Convert.Shell` is a .NET comhost, so the .NET 10 runtime must be installed. For a public release it
  should be rewritten as a native DLL (C++ or NativeAOT) so the app can ship self-contained.

### Windows-specific conversion notes

- Tools lookup (`Tools.cs`): `tools\` next to `Convert.exe` → PATH → winget's `Links` folder → winget
  package folders. Same for `ffprobe` and `soffice.exe` (LibreOffice).
- Hardware video encoding: on first use, Convert test-encodes a few frames with `h264_nvenc`, `h264_qsv`,
  `h264_amf` and uses the first that works; otherwise falls back to libx264/libx265. ProRes is always
  `prores_ks` (no hardware encoder on Windows).
- AAC uses ffmpeg's native `aac` encoder (`aac_at` is Apple-only).
- Documents: Markdown / plain text / HTML → PDF/HTML/TXT work without extra software (Markdig + WebView2
  printing from a hidden window on its own STA thread). Don't use Edge itself: it can be uninstalled in
  the EU, WebView2 can't. Anything involving DOCX/DOC/ODT/RTF needs LibreOffice
  (`winget install TheDocumentFoundation.LibreOffice`); the UI warns when it's missing.
- `Windows.Data.Pdf` renders pages larger than requested on scaled displays (×1.8 at 200 %);
  `PdfConv` resizes to the exact size so the dpi setting means the same everywhere.
- Images: Magick.NET reads HEIC but can't write it, so HEIC output goes through WIC's HEIF encoder
  (`WindowsHeif` in `ImageConv.cs`). That needs the Store's HEIF + HEVC extensions; a one-time probe
  encode decides whether the target is offered.

## Conventions

- Commit messages: short imperative summary line, like the existing history.
- Keep dependencies minimal; each one must earn its place (currently: Magick.NET, Markdig, PdfPig,
  WebView2 on Windows; none on macOS).
- Don't commit build output (`build/`, `.build/`, `windows/**/bin`, `windows/**/obj`, `windows/out/`) or
  signing material (`*.pfx`, `*.cer`).
